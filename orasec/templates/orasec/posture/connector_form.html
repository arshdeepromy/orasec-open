{% trans "Set-up notes" %}

{% with k=kind %} {% if k == "wazuh" %}

Base URL: Wazuh server API, e.g. https://wazuh.example.internal:55000. Username: an API user (read-only role recommended).

Options: {"indexer_url": "https://wazuh.indexer:9200", "vuln_product": "Infrastructure hosts", "sca": true, "alerts_level": 12}

Secrets: API password; indexer username/password (read access to wazuh-states-vulnerabilities-* and wazuh-alerts-*).

{% elif k == "opnsense" %}

Create a dedicated user in System → Access → Users with only the pages: Dashboard, System: Firmware, System: Trust: Certificates, System: User Manager, Interfaces: Overview. Add an API key to it.

Username: API key. Secret: API secret. Options: {"asset_name": "cloud-fw", "audit": true, "cert_warn_days": 30}

{% elif k == "unifi" %}

UniFi Network → Settings → Control Plane → Integrations → Create API key. Base URL: https://unifi.example.internal (the console). Leave username blank.

Options: {"site": "default", "clients": true}

{% elif k == "beszel" %}

Base URL: the Beszel hub, e.g. http://beszel.example.internal:8090. Username: a hub user's e-mail with the readonly role (set SHARE_ALL_SYSTEMS=true on the hub so it sees every machine). Secret: its password.

Each run adds every monitored machine to the asset inventory, so it appears on the Network Topology. Live CPU, memory, disk, network and temperature are read when the topology is open (cached a few seconds). A 15-minute interval is enough.

{% elif k == "patchmon" %}

PatchMon → Settings → Integrations → Auto-Enrollment & API → New token, usage type API, scope host:get only. Username: token key. Secret: token secret.

{% elif k == "plerion" %}

Plerion → Settings → API keys: create a read-only tenant API key. Base URL: the region host of your tenant, e.g. https://au.api.plerion.com. Leave username blank. Secret: the API key.

Options: {"providers": ["AWS"], "severities": ["CRITICAL", "HIGH"], "findings": true, "product_name": "Cloud"}

Only failed checks that are not exempted in Plerion are imported. A check that passes again is closed by the next run.

{% elif k == "tenable" %}

Base URL: https://cloud.tenable.com. Username: the API access key. Secret: the API secret key. Use a user that can view all assets; the connector only reads and exports.

Options: {"days": 90, "severities": ["critical", "high", "medium", "low"], "plugin_output": false, "product_name": "Infrastructure hosts"}

Imports assets assessed in the last days days and the vulnerabilities Tenable reports as open. An export takes a few minutes; an interval of 6 hours or more is enough.

{% elif k == "checkpoint" %}

In SmartConsole create a permission profile Read Only with Management API Login, and an administrator with that profile. The connector opens read-only sessions and sends only show-* commands.

Direct: Base URL = the Management API URL, e.g. https://mgmt.example.internal/web_api. Api key: the administrator's API key, or Username + Password.

Smart-1 Cloud through the portal: Base URL = the Authentication URL from the Portal API Keys page; Options: {"auth_mode": "portal", "client_id": "…"}; Portal secret = the Secret Key. The management administrator above is still needed for the rule base.

Other options: {"packages": ["Standard"], "domain": "", "product_name": "Network perimeter"}. TLS is always verified for this connector.

{% elif k == "aws" %}

An IAM user with the AWS-managed SecurityAudit and ViewOnlyAccess policies. Username: access key id. Secret access key: its secret. Session token: only for temporary credentials.

Leave the key blank to use the server's own identity (instance profile or task role). For another account: {"role_arn": "arn:aws:iam::<account id>:role/OraSecReadOnly", "external_id": "…"}, one connector for each account.

Options: {"regions": ["us-east-1"], "security_hub": true, "guardduty": true, "inspector": true}

{% endif %} {% endwith %}
