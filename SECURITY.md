# Security

## Reporting a problem

Please do **not** open a public issue for a security problem.

- Use **Report a vulnerability** on the repository's *Security* tab (GitHub private vulnerability reporting), or
- e-mail **security@oraflows.co.nz**.

Tell us what you found, how to reproduce it and which version or commit you tested. We aim to answer within five
working days. Once a fix is out we are happy to credit you, if you want that.

## Scope

This repository: the OraSec server (`orasec/`) and the mobile app (`mobile/`).

OraSec is self-hosted. Each organisation runs its own server, and we have no access to it. If you found a problem in
one particular installation (a weak password, an exposed server), please tell the organisation that runs it.

Problems in the DefectDojo core that OraSec is built on are best reported to the
[DefectDojo project](https://github.com/DefectDojo/django-DefectDojo/security) as well, so every user of that code
gets the fix.

## Please

- Test only against your own installation.
- Do not access, change or delete data that is not yours.
- No denial of service, spam or social engineering.

Research that follows these rules is welcome, and we will not take legal action against it.
